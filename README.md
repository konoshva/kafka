# Спринт 2. Реализация потоковой обработки на базе Apache Kafka
## Класс MessageNetwork
Реализует систему обработки потоков сообщений с функциями блокировки пользователей и цензуры сообщений. 
Для каждого получателя может динамически настраиваться список запрещенных отправителей, что немедленно блокирует сообщения 
от них к этим получателям. Кроме того, также может динамически настраиваться общий список запрещенных слов, которые в этом 
случае сразу же маскируются в новых пользовательских сообщениях. 

## Приложение работает со следуещими топиками:

### blocked_users
Предназначен для управления списком заблокированных отправителей для определенных получателей 

`Key` - строка формата: `<Recipient>;<Sender>`

`Value` - строка с возможными значениями:
* `blocked` - канал связи заблокирован
* `<AnotherValue>` или tombstone - канал связи разблокирован
### blocked_words:
Предназначен для управления списком запрещенных слов

`Key` - строка формата: `<BlockedWord>`

`Value` - строка с возможными значениями:
* `blocked` - слово заблокировано
* `<AnotherValue>` или tombstone - слово разблокировано

### messages 
Dходные пользовательские сообщения

`Key` - строка формата: `<Recepient>;<Sender>`

`Value` - строка формата: `<Message>`

### filtered_messages 
сообщения после фильтрации

`Key` - строка формата: `<Recepient>;<Sender>`

`Value` - строка формата: `<Message>`

## Описание логики работы приложения
Последние настройки, заданные на уровне пар `<Recepient>;<Sender>` в топике `blocked_users`, материализуются в постоянное 
хранилище `blocked-users-store`. Аналогично, последние настройки, заданные для `<BlockedWord>` в топике `blocked_words`, 
материализуются в постоянное хранилище `blocked-words-store`. При появлении сообщения в топике `messages` оно после 
фильтрации и маскирования попадает в топик `filtered_messages`.

## Инструкция по запуску приложения в режиме тестирования
В корневой папке находится `docker-compose.yml` файл разворачивания инфраструктуры. Сервис `message-network` 
содержит команду запуска потокового java-приложения, которая выглядит следующим образом:

    java -cp kafka-java-app-1.0.jar com.example.MessageNetwork test

Параметр `test` означает, что в топики будут загружены тестовые данные для демонстрации работы приложения. Если наполнения
тестовыми данными не требуется, удалите этот параметр. После сохранения файла запустите из корневой папки команду 
разворачивания инфраструктуры:

    docker-compose up -d

При отсутствии изменений в `docker-compose.yml` приложение запустится в режиме тестирования и наполнит топики тестовыми данными.
С помощью [Kafka UI](http://localhost:8080/) убедитесь, что развернут кластер Kafka с одним брокером, а содержимое топиков 
соответствует ожидаемым результатам:

**blocked_users**

| Key: \<Recipient>;\<Sender> | Value: blocked / unblocked |
|-----------------------------|----------------------------|
| Маша;Денис                  | blocked                    |
| Маша;Ярослав                | blocked                    |
| Маша;Денис                  | unblocked                  |

Таким образом, блокировке должны подвергнуться только сообщения, отправленные Маше Ярославом. 

**blocked_words**

| Key: \<BlockedWords>   | Value: blocked / unblocked |
|------------------------|----------------------------|
| дуб                    | blocked                    |
| коза                   | blocked                    |
| бред                   | blocked                    |

Тестирование можно продолжить в интерактивном режиме, добавляя и сообщения через [Kafka UI](http://localhost:8080/).
Для просмотра лога приложения можно использовать команду

    docker logs message-network

Список запущенных контейнеров (и их имена) можно получить командой:

    docker-compose ps

## Инструкция по реинициализации приложения после тестирования для запуска в рабочем режиме

Для реинициализации приложения после загрузки тестовых данных, например, для использования приложения в рабочем режиме без
тестовых данных нужно:
1. Удалить топики с помощью [Kafka UI](http://localhost:8080/)
2. "Свернуть" ранее развернутую инфраструктуру командой `docker compose down` 
3. Убрать в `docker-compose.yml` файле в сервисе `message-network` из команды запуска приложения параметр `test`
4. запустите из команду разворачивания инфраструктуры `docker-compose up -d`
